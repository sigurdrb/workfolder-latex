h1. How to use this page
*What this page is.* The variables the CAS (Heimdall) PLC publishes on its OPC UA server: every node, its data type, and what it does when you read or write it. It is generated from the CODESYS project (scaleaq/heimdall\-plc) and the notes in workfolder\-latex/CAS/OPC UA interface, so it follows the program. Do not edit the page by hand: change notes.json or the PLC and regenerate.
*Address space.* The server publishes the application's Symbol Configuration. Node ids are CODESYS string ids, ns=4;s=\|var\|<device>.Application.<GVL>.<path>, e.g. ...Application.GVLMain.Inlet\[0\].InletPump.Command.Reset. Device name and namespace index differ between PLCs: find GVLMain by browsing once per session. GVLMain is the only node structure exposed to clients; it is exported whole and read/write, so every member below is a node. The real PLC needs a user login (no anonymous access).
*Structure of a device.* Most devices use the same sub\-structures: Command (client writes: requests and setpoints), Status (PLC result: state, mode, permits), Input (measured values, after scaling), Output (what the PLC drives), Alarm (one AlarmState per alarm), AlarmAck (client writes to acknowledge), Config (settings; many are retained) and InternalCommand (between PLC blocks: never write). The column 'Client' says what a client may do with a node. Status, Input, Output, State and Alarm members are written by the PLC every scan; client writes are overwritten. Quality: analog sensors (AnalogSensorDUT) have Status.BadQuality (750\-455 diagnostic bits set, value out of range, or for level transmitters the InletRIO link down); control uses Filtered only when quality is good and Config.Enable is TRUE. Links: InletRIO/CommonRIO Status.CommOK = connected AND data fresh (a watched spare word must be rewritten within 2 s), DataStale = connected but no fresh data, Restarts counts automatic reconnects (every 10 s while stale). Inlet pumps: Status.CommunicationOK = Framo data source connected AND heartbeat answered; without it State is forced to Unavailable. Oxy pumps: Status.CommunicationOK = drive channel connected and fresh. Units: inlet pump speeds rpm; oxy pump Hz; levels and over\-height m; oxy pressures bar (absolute as the transmitter reads); O2 flow kg/h; pen O2 mg/L; saturation %; valve and outlet/cylinder positions %.
*Commands.* Commands are pulses unless stated otherwise: write TRUE, hold at least 1 s or until the PLC clears it, then write FALSE. Mode commands (Manual / Auto) are cleared by the PLC. A command the PLC cannot accept is ignored or reported (e.g. Pen.Status.CommandRejected); check the Status member named in the behaviour column for the result. Write only Command members, AlarmAck bits and the named settings; never Status, Input, Output, Alarm or InternalCommand. Command members are written by the client. Two kinds. Pulses (Manual, Auto, Reset, Pen Start/Stop/OxygenStart/OxygenStop, Cylinder CalibrateClosed/CalibrateOpen, Outlet FaultReset, HydraulicPump Start/Stop/Reset): write TRUE once; the PLC acts on the level it sees and writes FALSE itself, mostly in the same scan. Requests that the PLC keeps until done (InletPump/OxyPump Start and Stop): the PLC clears them only when the pump state confirms them. Levels (Setpoint, ManualSetpoint, ManualOutput, ManualPosition, Mode, LevelSetpoint, Cylinder Open/Close jog): the PLC reads the value every scan and does not clear it. Exceptions: OxyPump.Command.Reset is edge\-triggered and never cleared by the PLC (write TRUE, then FALSE). Manual/Auto pairs set Status.Manual; if both arrive in the same scan Auto wins. On the switch to manual the PLC copies the active value into the manual setpoint (bumpless), so ManualSetpoint / ManualPosition / ManualOutput are written by both PLC and client. The PLC gives no explicit acknowledge per command; the client sees the effect in Status (Status.Manual, State, Pen.Status.CommandRejected).
*Alarms.* Each alarm is an AlarmState (0 Normal, 1 Unacknowledged, 2 Acknowledged, 3 RetainUnacknowledged, 4 Suppressed). Acknowledge with a rising edge on the matching AlarmAck bit. Every alarm is an AlarmState byte (enum AlarmState: 0 Normal, 1 UnacknowledgedAlarm, 2 AcknowledgedAlarm, 3 RetainUnacknowledged, 4 Suppressed) in an \*AlarmDUT, with a BOOL of the same name in the matching \*AlarmAckDUT. AlarmManagement acknowledges on the RISING EDGE of the AlarmAck bit; the PLC never clears AlarmAck bits, so the client must write TRUE and then FALSE (a bit left TRUE will not acknowledge the next alarm). Transitions: Normal \-> Unacknowledged when the condition appears; Unacknowledged \-> Acknowledged on ack, or \-> RetainUnacknowledged if the condition clears first; Acknowledged \-> Normal when the condition clears; RetainUnacknowledged \-> Normal on ack, back to Unacknowledged if the condition returns. Suppressed (alarm disabled in config) overrides everything and returns to Normal when unsuppressed. Notification alarms (inlet LowPower, HighPower, FailedToReset) are auto\-acknowledged: they go straight to AcknowledgedAlarm and need no ack. Acknowledging only changes the alarm state; it never resets equipment. Equipment resets are separate commands (InletPump/OxyPump Command.Reset, HydraulicPump Command.Reset, Outlet Command.FaultReset). Exception: acknowledging Cylinder FlowSensorFault aborts a hanging counter set.
*Client rules.* Clients must follow 'CAS requirements for OPC UA clients of the PLC' (workfolder\-latex/CAS): one session, subscriptions instead of polling (>= 1 s), reconnect with back\-off, show values as unknown while the link is down, respect quality flags (BadQuality, CommOK).
*Config.* Config lives in GVLMain (PenConfig, InletConfig\[i\], OxyConfig\[i\], CommonRIOConfig, InletRIOConfig\[i\], Outlet.Config, Outlet.Cylinder\[i\].Config, sensor Configs). Main.UpdateRetain keeps a persistent copy in GVLRetain (VAR\_GLOBAL PERSISTENT RETAIN): on the first scan after start the retained copy is copied into GVLMain; after that any change in GVLMain is copied to GVLRetain in the same scan. So a client change is retained and survives a restart. Defaults for a fresh download come from ConfigValues (pfc200\_sim application) or, where it gives none, from the DUT initial values. Retained: InletConfig, InletRIOConfig, OxyConfig (OxySystemConfig), Outlet.Config, Cylinder Config, cylinder position counter and pressure sensor configs, CommonRIOConfig, PenConfig, Pen.Command.LevelSetpoint, Orbit864Sensor\[i\].Config, level inside/outside and over\-height sensor configs, oxy line sensor configs. NOT retained (back to DUT defaults after a restart): Orbit864 item configs (alarm limits, FilterTime), OxyValve config, Pen CO2/TGP/Turbidity/pH sensor configs, EstimatedInletFlow config, PID Command/Status. FBs read GVLMain config every scan, so most changes act at once. Exceptions are noted per member (e.g. Orbit864 SlaveAddress is read once at start\-up).
*Internal.* InletPumpDUT.InternalCommand (InletPumpInternalCommandDUT) is PLC\-internal: InletSupervisor/PumpCount writes AutoStart/AutoStop, InletControl writes Start/Stop/Reset/VelocitySetpoint/HeartbeatToggle, and FramoDataProcessing copies them to the Framo controller over OPC UA (data source Framo\_n). It is visible because it sits inside GVLMain.Inlet\[i\]; clients must not write it (the PLC overwrites it every scan, and a write between scans could reach the Framo controller). Also internal or unused despite being exported: GVLMain.InletSequence (PLC re\-sorts it every scan), Pen.InletSupervisor (unused copy; the live one is GVLMain.PenInletSupervisor), GVLMain.LevelController.Config and OxyController.Config (unused; tuning is in PenConfig).

h2. {anchor:PIDCommandDUT}PIDCommandDUT
Auto/manual pulses and the manual output of LIC01 or OIC01, handled by ControllerMode (bumpless both ways).
|| Member || Type || Client || Description || Behaviour, conditions ||
| *Manual* | BOOL | Command (client writes) | Put LIC01 (LevelController) or OIC01 (OxyController) in operator manual. | Pulse, cleared by ControllerMode every scan (Auto wins if both). Sets Status.Manual. If the loop is active, the PLC copies the current output into Command.ManualOutput (bumpless). LIC01 manual: pumps in REMOTE run at ManualOutput rpm each. OIC01 manual: total O2 flow = ManualOutput, shared over the lines in auto. Status.Manual is kept while the loop is idle. The oxy line PIC/FIC have no PIDCommandDUT. |
| *Auto* | BOOL | Command (client writes) | Return LIC01 or OIC01 to auto. | Pulse, cleared every scan. Clears Status.Manual; the PI restarts from the last output (bumpless). If the loop is active and the PV is good, the PLC sets the setpoint to the current PV: LIC01 overwrites Pen.Command.LevelSetpoint, OIC01 overwrites PenConfig.OxySetpoint (both retained). Auto while already in auto restarts the PI from its current output. |
| *ManualOutput* | REAL | Command (client writes) | Controller output in manual. \[rpm per pump (LIC01) / kg/h (OIC01)\] | Level value used while Status.Manual. LIC01: speed per pump in REMOTE \[rpm\], limited to PenConfig.LevelController.MinOutput..MaxOutput. OIC01: total O2 flow to the pen \[kg/h\]. Written by both: the PLC sets it to the current output on the switch to manual. |
